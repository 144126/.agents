# Weight-space programming

Treat an interpretation or proposed edit as a hypothesis. Define the behavioral goal, baseline, allowed inference and edit budget, and held-out tests before inspecting outcomes. Record checkpoint revision, architecture, tokenizer, dtype, seeds, prompts, decoding and every edit. Preserve the original checkpoint and export edits separately. Do not assume that a small edit preserves unrelated capabilities; measure them.

Use `wsr` for supported decoder-only safetensors models. `wsr --help` and `wsr <command> --help` are authoritative for the installed version. Run `wsr init` in a dedicated working directory, configure models and agents in `wsr.yaml`, then `wsr doctor`; use `wsr inspect <model>` to check detected anatomy. The bundled quickstart uses a toy suite and needs an actual target model; it is a smoke test, not evidence of general capability. `wsr run experiments/quickstart.yaml` executes pool, measure, label, select, materialize, read and report. `wsr program` proposes edits for a dataset-defined goal with held-out tests and guard suites. Consult the [upstream documentation](https://github.com/suayptalha/wsr) for configuration and commands. Model downloads and inference costs can be substantial. Use an isolated Docker or Apptainer sandbox for agent-generated code; local mode is not isolated. Check the sandbox image exists; installing the CLI does not build it.

For reading experiments, distinguish weight access plus tools from text-only descriptions, and compare the same edits and readers. Include no-op and subtle non-destructive edits, not only edits that collapse generation. Report change recall, specificity and balanced accuracy, uncertainty and the effect size; always-same is a 0.5 balanced-accuracy baseline. Ground truth requires independent target-model runs with multiple baseline seeds and meaningful effect thresholds. A failure to detect change is not proof of no effect. For self-reading, cross readers and targets and estimate the interaction rather than comparing self to one weaker reader.

Inspect architecture before choosing an edit: post-sublayer normalization can cancel uniform scaling; MoE experts, hybrid attention, tied embeddings, norm conventions, quantization and multimodal or auxiliary tensors affect meaning and validity. WSR refuses quantized checkpoints; inspect actual model support rather than assuming generality. Verify an exported checkpoint loads and test its behavior separately. Keep development and final test examples separate, and measure regressions on relevant guard tasks.

Research: [Weight-Space Reading](https://www.alphaxiv.org/abs/2611.weight-space-reading-language-models.pdf) reports 0.730 versus 0.578 balanced accuracy for one reader/target on subtle edits; self-reading superiority was inconclusive, and models often predicted changes for ineffective Muse edits. [Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/) describes reading, writing and repairing networks; its experiments use different tool and feedback budgets. These are early results, not proof that an arbitrary checkpoint can be reliably understood or repaired.
